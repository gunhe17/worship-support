The operational descriptions below state current implementation behavior, not ratified new product policies. PDF generation/retry requires Document EDIT permission (EDITOR/MANAGER), while download and metadata use current READ permission (D-01 resolved by the user on 2026-10-01).

Java 25, Spring Boot 4.1.1, Gradle 9.7.1 and MySQL 8.4. Gradle provisions a Java 25 toolchain through Foojay when needed. Docker must be running for MySQL Testcontainers; required integration tests are never silently skipped.

Run `./gradlew check` for each milestone and `./gradlew clean check` for the final gate. Run the application with `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` configured against a local MySQL database. Flyway owns all schema initialization, including Spring Session; Hibernate only validates. Never point automated verification at production. Current follow-up progress: [.agent/plans/active/backend-v1-team-ready.md](.agent/plans/active/backend-v1-team-ready.md); the original Core plan is historical evidence.

## Reproducible local setup

Start Docker, then `docker compose -f compose.local.yaml up -d --wait`. This creates a local-only MySQL 8.4 database on `127.0.0.1:13306`; example credentials are for this disposable environment only. Use `DB_URL='jdbc:mysql://127.0.0.1:13306/worship?connectionTimeZone=UTC' DB_USERNAME=worship DB_PASSWORD=local-only-worship ./gradlew bootRun`. Flyway migrates the empty DB and Hibernate validates it. Do not reuse these credentials in production. No SMTP/Google/YouTube provider or object storage is enabled by these commands; those operations deliberately fail until a test adapter or explicit integration is supplied. Integration tests supply fakes and their own disposable MySQL, independent of this database.

The default HTTP listener is suitable for API/local startup checks; browser session cookies remain Secure. For actual browser integration, provide a local HTTPS proxy or configured TLS rather than disabling the cookie policy. Test HTTP cookie handling is not a production HTTPS deployment proof. Stop the local database with `docker compose -f compose.local.yaml stop`; do not run cleanup against existing production volumes. This compose file defines no persistent volume, so removing its container loses the disposable local data.

The schema manifest is validated against live MySQL by DesignAssuranceIntegrationTest. The static HTTP contract is [openapi.yaml](src/main/resources/static/openapi.yaml). Human-readable relationships and field meanings live only in the table guide above; there is no separate ERD generator or generated reader artifact.

## Backend contracts and integration limits

Browser authentication uses JDBC sessions and CSRF. Obtain a token from `GET /api/auth/csrf` and send its named header on mutation requests. Cookies are Secure, HttpOnly and SameSite=Lax; use HTTPS for browser access. No domain roles are cached in sessions.

No external providers are enabled by default. Real provider integrations require explicit configuration. No Agent Runtime is included.

ADMIN transfer uses `POST /api/workspaces/{workspaceId}/members/{memberId}/transfer-admin`; the previous independent `/promote` endpoint is removed. Both roles, scoped Audit and the new ADMIN's in-app notice commit atomically. DocumentGrants are unchanged. V13 rejects existing multiple ACTIVE ADMINs without selecting a survivor. Before deploying an upgrade from V12 or earlier, inspect `SELECT w.id, COUNT(m.id) FROM workspace w LEFT JOIN workspace_membership m ON m.workspace_id=w.id AND m.state='ACTIVE' AND m.role='ADMIN' GROUP BY w.id HAVING COUNT(m.id)<>1`. On V16 or later, add `WHERE w.state='ACTIVE'` before GROUP BY: terminated workspaces correctly have zero ACTIVE ADMINs. A unique index is only an at-most-one backstop, not a repair for legacy active spaces with no ADMIN. Resolve invalid legacy data explicitly; automated verification never performs production correction.

Own notices use `GET /api/account/notices?beforeId={optionalCursor}` (descending IDs, at most 100) and `POST /api/account/notices/{noticeId}/read` with CSRF. Notifications do not grant authority and contain no emails/titles. Read markers are idempotent. Role notices require current ACTIVE recipient membership and, for a document notice, current READ access. ADMIN/MANAGER assignment, succession and termination publish notices in the mutation transaction. Termination notices alone allow their own historical recipient to see minimal information after membership ends.

Workspace termination: ADMIN obtains `GET /api/workspaces/{workspaceId}/termination-impact`, reviews counts/warnings and retypes the current name with `POST .../terminate` (`workspaceName`, `confirmation`). Changed impact returns 409, not automatic reconfirmation. The fingerprint is not authentication or evidence that a human read the warning. DB commit ends all ACTIVE memberships, revokes pending invitations and records own notices; no data hard deletion or reopen endpoint. Closed content routes return 404 and list omits the workspace. `GET /api/account/workspaces/{workspaceId}/termination` exposes only workspaceId/state/terminatedAt to termination-time recipients, not unrelated or earlier departed users. Provider-completed effects cannot be rolled back reliably; late ordinary result commits are denied while failure/cleanup records remain observable internally. ongoingWork explicitly covers persisted RUNNING PDF/Playlist commands, not every synchronous network call.

Own `GET/PUT /api/account/profile` manages an optional display name (1–80 characters, no controls). No email-derived backfill or public user editing exists. Workspace members and MANAGER-only document Grant lists show joined display names, never emails. Names do not confer authority, may be duplicated and are cleared on service withdrawal. Unset names display as `이름 미설정`.

For sole-MANAGER MEMBER removal, `GET /api/workspaces/{workspaceId}/members/{memberId}/removal-impact` returns only affected-document count and a current-state fingerprint; no restricted titles/IDs. Pass `confirmation` to the DELETE member request. Missing confirmation when succession is needed, or changed impact, returns 409 and requires a fresh preview. Current ADMIN/member checks remain mandatory: the fingerprint is not an authentication or permission token. Grant acquisition, document version updates, membership end, scoped Audit and notices commit/rollback together. Other remaining MANAGERs suppress inheritance. Voluntary leave/withdraw still requires explicit responsibility transfer. Own `/responsibilities`, READ-authorized document `/permissions` and MANAGER-only `/grants` support frontend hints without replacing backend authorization.

Identity capabilities are under `/api/auth` and `/api/account`. Verification/resets return no raw tokens through HTTP; delivery happens through EmailSender after the account transaction commits. Failed delivery is recorded and can be retried with resend capabilities. Tokens expire (verification: 24 hours, reset: 30 minutes) and are stored as SHA-256 hashes. Passwords use Argon2id and accept 12–128 characters. Recent reauthentication lasts 5 minutes.

SMTP is enabled only with `worship.email.enabled=true`, `worship.email.from`, `worship.email.browser-url` and Spring Mail host/credentials. Configuration must target an intentional provider or local test server. Google OIDC uses an explicitly configured Spring OAuth2 client registration named `google` with scopes `openid,email,profile`; no client credentials or provider are configured by default. Direct authorization entry is `/oauth2/authorization/google`; linking and Google reauthentication require the respective CSRF-protected `/api/account/google/*-intent` action before redirecting. The callback validates signature, issuer, audience, state, nonce and a single-use server-side intent. Google login does not confer YouTube authorization.

Score storage is disabled until `worship.storage.local.enabled=true` explicitly enables the local filesystem adapter (root defaults to ignored `.local/objects`), or an ObjectStorage adapter is provided. Score defaults allow PDF/PNG/JPEG up to 20 MiB (`worship.scores.max-bytes`); actual parsing and MIME checks apply. Images are limited to 25 million pixels. Set multipart limits consistently when changing upload size. Storage calls happen outside DB transactions; upload/DB failures trigger compensation, with unsuccessful deletion recorded in `storage_cleanup_failure` for operator inspection. No automatic production cleanup is performed.

All Setlist mutations—including Score/Reference selection—require the current Document `expectedVersion`. Search returns transient candidates; registration is explicit and titles are never auto-merged. Reference URLs accept absolute HTTP(S) URLs without userinfo and are never fetched by the backend.

YouTube is a separate authorization: `/api/account/youtube/connect` returns a single-use, account/session-bound PKCE authorization URL; the authenticated callback records an encrypted refresh token. Configure `worship.youtube.enabled=true`, `worship.youtube.client-id`, `worship.youtube.client-secret`, `worship.youtube.redirect-uri` and a base64-encoded 32-byte `worship.credentials.key` only for intentional provider access. Public video search additionally requires `worship.youtube.api-key`. Never commit these secrets. Google login/linking does not authorize YouTube.

Playlist commands require Document EDIT permission, `sourceVersion` and a workspace-unique `commandKey`; optional `playlistId` selects an existing playlist. External operations do not mutate the internal Setlist. `FAILED_RETRYABLE` preserves a known playlist ID; `UNCERTAIN` creation is reconciled by an opaque marker and never blindly creates another playlist. Concurrent duplicate keys return RUNNING; after five minutes a stale operation can be reconciled. Disconnect always removes local credentials even if provider revocation fails. Withdrawal discards local credentials without a provider call inside its transaction.

Exports live under `/api/workspaces/{workspaceId}/documents/{documentId}/exports`: POST `{sourceVersion, commandKey}`, GET list/metadata, and GET `/{exportId}/download`. Generation/retry requires current Document EDIT permission (EDITOR/MANAGER), checked again at artifact commit; metadata/download use current READ permission. Neither operation grants access or creates public links. A canonical snapshot is persisted before PDF rendering/storage; retries retain that exact snapshot even if the source changes. Successful artifacts are immutable, content-hashed PDFs with Korean fonts embedded under SIL OFL. Download verifies artifact integrity and current authorization. Failed rendering/storage/commit is observable as FAILED_RETRYABLE; unsuccessful storage compensation is recorded for operator inspection. Concurrent/stale attempts are fenced by attempt IDs. Unsupported font glyphs are displayed as explicit Unicode codepoints; canonical JSON preserves original text. PDF export includes a summary and each song's musical settings, notes, SongForm and Reference URLs, followed by all selected PDF Score pages or a PNG/JPEG image. Original PDF crop/rotation and inherited resources are retained. Executable page/annotation actions are removed; this is not a claim of complete malicious-PDF sanitization.

Export defaults: unique selected Score input total 100 MiB (`worship.exports.max-input-bytes`), total output 500 pages including guidance (`worship.exports.max-pages`), serialized output 100 MiB (`worship.exports.max-output-bytes`). These are implementation safeguards, not approved product quotas or hard execution-time/heap limits. Rendering and Score reads happen outside long DB transactions. Retry reads immutable Score IDs from the frozen snapshot, not the current selection. ObjectStorage adapters must enforce write-once keys; a different file requires a new Score/key. Real provider adapter acceptance, production load and browser UI integration remain separate.

Playlist workers also use attempt fencing: a superseded worker cannot overwrite terminal results, and the HTTP adapter rechecks current authorization/execution ownership before each item mutation, renewing its lease in a short transaction. Network requests remain outside transactions. Disconnect cancels in-flight OAuth intents, so a late token exchange cannot restore local authorization; rejected late credentials are best-effort revoked. This does not provide provider-side atomicity: partial external changes remain observable and are repaired by explicit retry/reconciliation, while the internal Setlist is never rolled back.
