## 1. 주보(bulletin) + 인도자 묵상

### 기본 구조
- 목사님께 받은 내용(말씀 본문, 설교 제목, 설교 방향성, 설교 주제)을 **복사-붙여넣기** 입력
- LLM이 이를 받아 **주보 형식**으로 자동 변환
- 생성된 주보는 커뮤니티 글(예배 포스트) 안에서 바로 볼 수 있는 구조여야 함

### 인도자 묵상 (묵상 입력란)
- 동일한 글 안에 묵상 작성 공간 포함
- 분량 제한 없음 — 인도자가 쓰고 싶은 만큼 자유 작성
- **AI 작성 추천 기능 없음** (제거)
- 묵상은 순수하게 인도자 본인의 생각을 적는 공간

### 포스트 구성 요소 (하나의 글에 포함되는 것들)
```
[ 말씀 본문 ]
[ 주보 (LLM 생성, 수정 가능) ]
[ 인도자 묵상 (자유 작성, 분량 제한 없음) ]
[ 콘티 전체 내용 (아래 3번 참고) ]
```

## 2. CCM 곡별 송폼 DB

### 핵심 개념
- 각 CCM 곡마다 **가사를 DB에 저장**
- 가사의 각 부분을 직접 구간 지정: INTRO / VERSE1~4 / PRE-CHORUS / CHORUS / BRIDGE / INTERLUDE / OUTRO 등
- 마디수는 구간별로 DB에 함께 저장 (관리자/기여자가 직접 입력)
- 텔레프롬프터에서 "마디수 직접 입력" 방식 → **DB 조회 방식으로 교체**

### 기존 마디수 입력 방식 폐기
- 기존: 사용자가 INTRO=8마디, VERSE=16마디 직접 타이핑
- 변경: DB에 저장된 구간 데이터를 불러와서 드래그로 **배치 순서만 변경**
- 사용자는 곡의 구간을 선택하고 순서를 조정하는 것에 집중

### 데이터 구조 (예시)
```
songs: id, title, artist, bpm, key
song_sections: id, song_id, section_type, section_label, lyrics, bars, order
```

### 송폼 편집 UX
- 저장된 구간 목록에서 드래그 앤 드롭으로 순서 변경
- 구간 추가/제거 가능
- 각 구간에 멘트 작성 연결

## 3. 불편한 커뮤니티

### 핵심 철학
- **검색 기능 없음** — 이게 "불편함"의 핵심이자 의도
- 특정 말씀이나 설교 방향으로 찾는 게 아니라, **피드를 보다가 우연히 발견**하는 구조
- "이 인도자는 이 말씀으로 이런 묵상을 하고, 이런 콘티를 짰구나"를 발견하는 경험

### 피드 정렬
- 최신순
- 조회순
- (말씀 책 순 없음 — 의미 없음)

### 각 포스트(카드)에 포함되는 내용
```
[ 말씀 본문 ]
[ 인도자 묵상 — 분량 제한 없이 전체 노출 or 펼치기 ]
[ 콘티 전체 ]
  - 곡 목록 (순서 포함)
  - 각 곡의 송폼 (INTRO → VERSE1 → CHORUS → ...)
  - 각 구간별 멘트
  - 악보 (추후 기능)
[ 가져오기 버튼 ] — 이 포스트의 콘티 전체를 내 예배로 복사
```

### 가져오기 기능 (복붙)
- 다른 인도자의 콘티(곡 순서 + 송폼 + 멘트 전체)를 **내 예배에 그대로 가져오기**
- 가져온 후 자유롭게 수정 가능

### 소셜 기능
- 댓글 가능
- 좋아요 없음

## 4. 악보 / 코드 생성

### 결론: AI 자동 생성은 현시점에서 보류

**이유**:
- LLM이 알고 있는 한국 CCM 코드 정보는 정확도가 일관되지 않음
- 틀린 코드를 자신있게 출력할 위험이 있음
- 음표 악보 자동 생성(LilyPond 등)은 데이터 입력 난이도가 매우 높음

**현실적인 방향**:
- 곡별 구간 DB에 **코드 필드 추가** (`Am - G - F - C` 형태)
- 초기에는 관리자/커뮤니티 기여로 직접 입력
- 추후 ChordPro 형식으로 렌더링 지원 고려

## 5. 예배 인도 모드 — 악보 위 필기 / 어노테이션

### 개요
- 예배 인도 모드(왼쪽 악보 영역 | 오른쪽 멘트 패널) 에서
  악보 위에 직접 **필기·메모를 덧씌울 수 있는** 어노테이션 레이어 추가
- 악보 자체를 수정하는 게 아니라 **투명 캔버스를 위에 얹는** 방식

### 디바이스별 인터랙션
| 환경 | 입력 방식 |
|------|-----------|
| 아이패드 + 애플 펜슬 | 펜슬로 직접 필기 (Pointer Events API — `pointerType: "pen"`) |
| 아이패드 (손가락) | 터치 드로잉 |
| 노트북 (마우스/트랙패드) | 클릭-드래그로 선 그리기, 텍스트 입력 가능 |

### 기능 범위
- 자유 곡선 드로잉 (색상·굵기 선택)
- 텍스트 박스 추가 (짧은 메모, 코드 표기 등)
- 지우개
- 실행 취소 / 다시 실행 (undo/redo)
- **저장 버튼** → 어노테이션 데이터를 DB에 저장 (SVG Path 또는 JSON 좌표 배열)
- 저장된 어노테이션은 다음 인도 시 자동 불러오기

### 기술 고려사항
- `<canvas>` 위에 Pointer Events로 드로잉 구현
- 어노테이션 데이터는 곡(song_id) 또는 예배(worship_id) 단위로 저장
- 악보 이미지는 변경하지 않고 레이어만 저장 → 악보와 필기 분리 유지

## 6. 제거할 기능

| 기능 | 이유 |
|------|------|
| AI 찬양 추천 | 제품 방향과 맞지 않음 |
| AI 묵상 작성 추천 | 묵상은 인도자 고유의 것 |
| 말씀 책 순 정렬 | 의미 없음 |
| 좋아요 | 커뮤니티 철학과 충돌 |

---

## 7. 개발 우선순위 (잠정)

1. **CCM 곡별 구간 DB 설계 + 관리 화면** — 모든 기능의 기반
2. **불편한 커뮤니티 피드 + 포스트 작성** — 곡 DB 위에서 동작
3. **가져오기(복사) 기능** — 커뮤니티 핵심 가치
4. **LLM 주보 생성** — 독립적으로 추가 가능
5. **코드 DB + 렌더링** — 이후 단계
6. **악보 필기 어노테이션** — 인도 모드 완성도 단계
