# 10/19 회의 전 역할 및 완료 기준

## 공통 원칙

- 각자 맡은 영역은 구현 목록이 아니라 **설계 근거까지 설명 가능한 상태**로 가져온다.
- 외부 AI·인프라가 아직 없어도 전체 흐름 개발을 멈추지 않는다. 외부 경계는 Mock/Stub으로 대체해 연결 전후 계약과 사용자 흐름을 먼저 완성한다.
- 성진과 성민은 공통 디자인 레퍼런스로 사용할 **실제 서비스 또는 디자인 시스템 1개**를 함께 선정하고, 프론트 UI는 그 기준에 맞춘다.
- 가능하면 약간의 코드로 아키텍처를 설명 가능한 경지를 지향한다.

## 성진 — Backend

### 담당

- User, Member, Workspace, Document, 권한 영역의 정책 및 테이블 모델 확정
- 관리자 1명, Member 재가입, OWNER 이전, OPEN/RESTRICTED, OWNER/EDITOR/VIEWER 정책 반영
- Soft Delete 기준과 tenant/삭제 상태를 고려한 조회 경계 설계
- 성민과 디자인 레퍼런스 선정

### 완료 기준

- 핵심 엔티티 관계와 제약을 설명할 수 있음
- 자발적 나가기/강제 퇴장/OWNER 이탈/관리자 이전 시나리오를 끝까지 설명할 수 있음
- 왜 해당 모델을 선택했는지 대안과 함께 설명 가능

## 성민 — Frontend / 예배 자료 구조

### 담당

- 곡, 콘티, 블록, 템플릿 등 예배 자료 전체 구조와 관련 데이터 모델 설계
- Document·Template·실제 생성 결과물의 관계 재설계
- ServiceOccurrence의 책임이 필요한지, 다른 구조로 대체할 수 있는지 검토
- 건희가 제공하는 **AI 분석 결과 이후**의 곡 요소 선택·콘티 편집·자료 활용 UI 흐름 설계
- 사용자 관점의 프론트 UI를 빠르게 구현
- 성진과 디자인 레퍼런스 선정

### 완료 기준

- 예배 자료 엔티티 관계와 생성/편집/재사용 흐름을 설명할 수 있음
- Document·Template·결과물 경계에 대한 추천안을 제시할 수 있음
- AI 분석 결과가 없어도 Mock 데이터로 핵심 화면 흐름을 시연할 수 있음

## 건희 — LLM / AI 분석

### 담당

- 신경망 학습
- STT 모델을 이용한 가사 추출
- 악보에서 코드·오선·가사를 추출하는 전처리 검토
- 가사와 악보 매칭을 통한 송폼 파악 및 송폼별 Key 추출
- BPM 관련 작업 정리 및 Key 추출 작업 지속
- **YouTube 링크 입력 → AI 분석 → BPM·Key 등 곡 요소 후보 제공/선택 가능한 결과 생성**까지 담당
- 프론트 아키텍처 검토안 준비

### 완료 기준

- 성민이 Mock으로 대체할 수 있도록 AI 분석 입력/출력 경계를 설명할 수 있음
- 현재 가능한 기능과 아직 불확실한 기능을 구분해 제시할 수 있음
- BPM·Key·송폼 분석 흐름의 현재 진행 상태와 다음 실험 항목을 설명할 수 있음

## 연결 경계

개발 중 AI 분석 인프라가 아직 준비되지 않았을 때는 다음 경계를 임시 계약으로 사용한다.

`YouTube 링크 입력 → [Mock AI 분석] → BPM/Key/기타 곡 요소 후보 → 사용자 선택 → 예배 자료 편집 흐름`

Mock은 임시 구현일 뿐 최종 AI 결과 형식을 임의 확정하는 용도가 아니다. 건희가 실제 분석 결과 스키마를 제시하면 해당 경계를 교체한다.
